# Evaluation Candidate Prompt Contract

A target-model evaluation job is not executable evidence until it contains the exact prompt candidate that will be sent to the target model.

The evaluation pipeline has two distinct stages:

1. **Candidate materialization** — produce the exact `legacy`, `neutral`, or `v4` prompt candidate from the same case specification.
2. **Target execution** — send that immutable candidate to the target model/runtime and record the outcome.

Do not skip stage 1. Sending the raw holdout case prompt directly to every target measures model capability, not prompt-strategy quality.

## Candidate fields

Every executable job must contain:

```json
{
  "case_prompt": "original holdout task description",
  "candidate": {
    "prompt": "exact prompt sent to the target model",
    "prompt_sha256": "64 lowercase hexadecimal characters",
    "generator_model": null,
    "generator_runtime": null,
    "materialized_at": "RFC3339 timestamp",
    "materializer_revision": "repository revision or external materializer revision"
  }
}
```

`generator_model` and `generator_runtime` may be null only when the candidate is produced deterministically without a model call.

## Strategy invariants

- `legacy`: candidate must come from the frozen legacy strategy or an explicitly labelled forced-legacy adapter.
- `neutral`: candidate must contain the task goal, supplied context/source constraints, output contract, and permission boundary without model-specific optimization.
- `v4`: candidate must use the v4 Prompt Contract + Core + primary Task Profile + only applicable Confirmed/Evaluated Model Delta + user requirements.
- `v4-experimental`: must be explicitly selected and must never be mixed into `v4` evidence.

## Immutability

The executor must not rewrite, enrich, shorten, translate, or otherwise optimize `candidate.prompt`. Provider-specific transport wrapping is allowed only when it preserves the candidate text and is recorded in runtime metadata.

The executor must copy `candidate.prompt_sha256` into `inputs.prompt_sha256` in the result. The import validator must reject mismatches.

## Evidence boundary

A plan containing only case metadata is a planning artifact, not executable evidence. A candidate generated by an unrecorded model or modified after hashing is not reproducible evidence.
